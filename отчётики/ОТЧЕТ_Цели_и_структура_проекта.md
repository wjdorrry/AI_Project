# Отчёт: цели, актуальность и постановка проекта «Sillage&Style»

Документ дополняет общий отчёт по проекту и предназначен для раздела курсовой/практики «Цели и задачи», «Объект и предмет исследования», «Входные данные».

---

## 1. Актуальность темы

Подбор парфюма под образ одежды традиционно опирается на субъективный опыт консультанта или на обобщённые рекламные образы. При этом у потребителя и у специалиста по стилю часто нет **прозрачного, воспроизводимого правила**, связывающего конкретные визуальные признаки одежды (цвет, фактура, стиль) с **семействами ароматов** (цитрус, древесные, восточные и т.д.).

**Актуальность** темы состоит в следующем:

- растёт интерес к персонализации рекомендаций в e-commerce и beauty-сервисах;
- компьютерное зрение позволяет **автоматически извлекать теги** с фотографии образа, снижая нагрузку на пользователя;
- **экспертная система** с явной **матрицей весов** делает вывод **объяснимым** (можно показать вклад тегов и ограничений), что важно для учебных проектов по дисциплине «Экспертные системы» и для доверия к рекомендации.

Таким образом, тема объединяет практическую пользу (помощь в выборе «настроения» аромата под look) и методическую ценность (формализация знаний эксперта в виде правил и числовых коэффициентов).

---

## 2. Цель работы

**Цель проекта** — разработать программный комплекс (веб-приложение), в котором:

1. по **цифровому изображению** образа одежды формируется набор **признаков** (теги: цвета, стили и при необходимости материалы);
2. эти признаки обрабатываются **экспертной подсистемой** на основе **базы знаний** (матрица соответствия тегов парфюмерным семействам с весами от −10 до +10);
3. пользователь может задать **жёсткие ограничения** (например, исключить цитрусовые ноты), которые **полностью** убирают соответствующие семейства из итоговой рекомендации;
4. на выходе пользователь получает **осмысленное объяснение**: какое семейство ароматов рекомендуется и с каким суммарным баллом по выбранным тегам.

**Что именно должен «делать ИИ» в рамках цели:**

- на этапе **визуального анализа** — автоматически (или в учебном прототипе — с имитацией) сопоставлять изображение с **метками из заранее заданного словаря** тегов, согласованного с матрицей весов;
- на этапе **логического вывода** — не подбирать аромат «наугад», а **агрегировать веса** по правилам экспертной системы и учитывать пользовательские запреты.

То есть ИИ здесь выступает в двух ролях: **модуль распознавания признаков** (нейросетевая или API-модель компьютерного зрения) и **нечётко-логический / взвешенный вывод** по явной базе знаний (реализуется алгоритмом на стороне клиента или сервера).

## 3. Объекты исследования

   **Объекты исследования** в проекте можно сформулировать так:

   | Объект | Суть | Методы обнаружения / получения | Где используется |
   |--------|------|--------------------------------|------------------|
   | Визуальные признаки образа | Цвета, категория стиля (спорт, вечер, улица и т.д.), при расширении — фактуры и материалы | **Классификация и/или тегирование изображения** с помощью предобученной нейросети (мультилейбл) или облачного API (Google Cloud Vision, Azure Computer Vision и т.п.); альтернатива — open-source модели на **Hugging Face** (например, vision-language или image classification под домен одежды) | Модуль «изображение → теги»; в текущем прототипе теги вводятся вручную для демонстрации цепочки без доступа к API |
   | Правила соответствия «тег → семейство аромата» | Числовые веса в матрице | Заданы экспертом (методика курса, таблица Excel); хранятся в **JSON** | Экспертный движок суммирования и выбора победителя |
   | Пользовательские ограничения | Запрет отдельных парфюмерных семейств | Ввод с интерфейса (переключатели «Без …») | Фильтрация кандидатов перед выбором максимума балла |

   Итого объект исследования с точки зрения **ИИ** — это прежде всего **надёжное извлечение тегов с фото**; с точки зрения **экспертных систем** — **корректное применение матрицы весов и ограничений**.

## 4. Предмет исследования: нейросети, модель, взаимодействие ИИ и сайта

**Предмет** — применение **нейросетевых моделей компьютерного зрения** (или готовых сервисов на их основе) для **получения структурированного описания образа** и **организация взаимодействия** этого описания с веб-приложением и экспертным модулем.

**Какие нейросети и модели уместны (план / варианты реализации):**

- **Мультиклассовая или мультилейбл-классификация** изображений под набор тегов, совпадающий с базой знаний (цвета, стиль). Модель: свёрточная сеть (ResNet, EfficientNet) или Vision Transformer в зависимости от выбранной платформы.
- **Обобщённое тегирование** через API: модель возвращает список лейблов на английском; на стороне приложения выполняется **сопоставление** (mapping) лейблов API со строками матрицы (например, `Black`, `Sportswear`).
- **Vision + язык** (CLIP-подобные или captioning-модели) — опционально для расширения: из текста описания извлекаются ключевые слова и приводятся к тегам матрицы.

**Организация взаимодействия между ИИ и сайтом (логическая схема):**

1. **Браузер:** пользователь загружает файл изображения (или снимает фото).
2. **Клиент или промежуточный backend:** изображение кодируется (например, Base64 или `multipart/form-data`) и отправляется в **эндпоинт**, вызывающий API нейросети / inference-сервер.
3. **Сервис ИИ:** возвращает JSON с тегами и уверенностями (или сырой список меток).
4. **Сайт (React):** нормализует теги к словарю матрицы, передаёт массив в **функцию экспертной системы** (`computeScores` и аналоги).
5. **Интерфейс:** отображается карточка результата, опционально — список распознанных тегов для проверки пользователем.

В **текущей реализации** без бэкенда шаги 2–3 заменены **ручным выбором тегов** на странице; архитектура рассчитана на последующую подстановку реального API без переработки матрицы и правил вывода.

## 5. Постановка задач и требований

**Задачи:**

1. Формализовать базу знаний в виде матрицы весов (тег × семейство аромата) и хранить её в **JSON**.
2. Реализовать алгоритм: суммирование весов по выбранным тегам, исключение семейств по жёстким ограничениям, выбор семейства с максимальным итоговым баллом среди допущенных.
3. Обеспечить **веб-интерфейс**: загрузка изображения (превью), выбор/отображение тегов, переключатели ограничений, наглядный результат.
4. (Перспектива) Подключить **модуль распознавания** по API или локальному inference.

**Требования:**

- согласованность словаря тегов с матрицей;
- детерминированность вывода при одинаковых входах;
- учёт **hard constraints** (исключённые семейства не могут стать рекомендацией);
- возможность расширения числа тегов и семейств без смены общей схемы;
- для учебной демонстрации — работа прототипа **без обязательного сервера** (клиентская логика + ручные теги).

## 6. Входные данные: получение цифрового изображения образа

**Входные данные** для системы в полном варианте:

1. **Цифровое изображение** — файл растрового формата (JPEG, PNG, WebP и т.д.), полученный:
   - загрузкой с устройства пользователя;
   - либо (при расширении) захватом с камеры в браузере.
2. **Метаданные интерфейса** (не из нейросети):
   - множество **активных тегов** (после распознавания или ручного уточнения);
   - множество **исключённых парфюмерных семейств** (пользовательские предпочтения).

**Преобразование в форму, удобную для ИИ:**

- изображение приводится к требованиям выбранной модели (размер, нормализация) на стороне API или inference;
- на выходе ИИ формируется **структурированный список тегов** (строки, совместимые с ключами в JSON-матрице).

Таким образом, **первичный вход** системы — **изображение образа**; **фактический вход экспертного модуля** — **массив тегов** плюс **ограничения**, что отделяет «перцептивную» часть (нейросеть) от «рассуждающей» (матрица и правила).

## Краткое резюме для введения отчёта

- **Актуальность:** персонализация и объяснимые рекомендации в связке «визуальный стиль — парфюм».  
- **Цель:** рекомендация парфюмерного семейства по тегам образа с учётом матрицы весов и жёстких запретов.  
- **Объекты:** признаки с изображения, правила матрицы, пользовательские ограничения.  
- **Предмет:** применение моделей компьютерного зрения для тегирования и схема обмена данными с веб-приложением и экспертным ядром.  
- **Задачи и требования:** JSON-база, алгоритм вывода, UI, задел под API.  
- **Входные данные:** цифровое фото образа → (после ИИ) теги + настройки пользователя.
